# Attack step 3 of the scout's order (B2, B3) — indexes and foreign keys

Source of truth: `adws/adw_data/sessions/6f231271/context_handoff/scout_findings.md` (findings B2, B3 carry the file:line, proposed fix, cost and risk). Fix them in this order.

- **B2** `clreview/db.py` SCHEMA has indexes only on `components_key(components)`, `matches_pair(matches)` and `decisions_key(decisions)`. Every hot request path full-scans: `matches WHERE mapping_id=?`, `snapshots WHERE mapping_id=? AND side=? AND status='ok'`, `sync_items WHERE job_id=?`, the audit subqueries in `service.py`, `notes.match_id`, `suggestions.match_id`. Add `CREATE INDEX IF NOT EXISTS` for `matches(mapping_id)`, `snapshots(mapping_id, side, status)`, `sync_items(job_id)`, `notes(match_id)`, `suggestions(match_id)`, `audit(entity_type, entity_id)` — `IF NOT EXISTS` so existing databases pick them up on next start.
- **B3** the SCHEMA declares `REFERENCES ... ON DELETE CASCADE` on 8 tables but no connection ever issues `PRAGMA foreign_keys=ON`, so nothing is enforced and deleting a mapping leaves orphan snapshots/components/decisions forever. Enable it per connection where the connection is opened. Before enabling, run `PRAGMA foreign_key_check` against the existing `clreview.db` in this repo and against a freshly built test DB; if pre-existing rows violate a FK, say so in the plan and handle it deliberately rather than letting later writes fail.

Where: `clreview/db.py`, plus the tests that cover it (`tests/test_db_concurrency.py`, `tests/test_db_concurrency`-adjacent DB tests, `tests/test_review.py`, `tests/test_sync.py` — add new DB tests where they belong)
Done means: `uv run pytest -q --ignore=adws` is green with the coverage gate still passing; after opening a connection, `PRAGMA foreign_keys` returns 1 and `sqlite_master` lists all six new indexes; a new regression test deletes a mapping and asserts zero orphan rows in the cascaded tables; the `PRAGMA foreign_key_check` result on this repo's `clreview.db` is reported in the plan.
Out of scope: B1 and B4–B9, every A/C/D/E/F finding, query rewrites, ORM or schema redesign, data migrations beyond what B3 forces, changes to `clreview/db.py:141-166`'s locking.
